# バックアップ先の設定（Issue #51）

## 操作

CPU・イベント・統合付与の各画面で、ソースパスの下にある「バックアップ先」を指定する。
フルパスの入力、または「保存先を選択…」でフォルダーを選べる。存在しないフォルダーも入力でき、適用時に作成する。
設定は画面ごとに保存し、次回起動時も復元する。バックアップ先だけの変更ではプレビューを破棄せず、再解析も不要。

初期値は `%LOCALAPPDATA%\UEEtc\Backups`。
適用ごとに `<バックアップ先>/<UTC日時>-<GUID>/<元ファイルの相対パス>` へ元のバイト列を保存する。
確認ダイアログと画面下部に保存先を表示し、適用完了時には実際に作成したサブフォルダーのパスを表示する。
解析やプレビューだけではバックアップを作らない。

Consoleでは、CPU・統合・イベント・従来の関数進入カウンターの各コマンドで `--backup-dir` を使用する。

```powershell
dotnet run --project src/UEEtc.Console -- combined D:\Game\Source --backup-dir E:\UEEtcBackups --apply
```

省略時はWPFと同じ初期値を使用する。WPFの画面別設定はConsoleへ引き継がない。
従来の `.ueetc-backups` は新規保存先に使わず、残っている既存バックアップの自動移動・削除は行わない。
解析時の旧バックアップフォルダー除外は維持する。

## 共通処理と適用条件

- `BackupStorage` が初期値と保存先の正規化・検証を担当する。空欄・相対パス・ソース自身とその子フォルダーは拒否する。
  リンク・ジャンクションを含むパスも既存のパス検証で拒否する。
- `SourceWorkspace.Apply(plan, backupRoot)` が適用先の状態を検証し、指定先に全件のバックアップを作ってから元ファイルを書き換える。
  作成先がファイルだった場合や権限・容量不足などで保存できなければ元ソースは変更しない。
  部分的なバックアップが残る場合はある。書き込み開始後の失敗には既存の復元処理を使用する。
- `BackupLocationPicker` は3画面で共用する入力UI。`RememberedInputs` で画面別の `BackupRoot` を保存する。
- `PlanAvailability` は入力を検証し、不正な保存先では適用だけを無効にする。レポート出力とプレビュー確認は可能。
  `PlanFileActions` が確認時の保存先を固定してCoreへ渡す。

## 検証

- Releaseソリューションビルド: 警告0・エラー0。
- Core 134/134: 外部保存先、元バイト一致、複数回の保存先分離、ソース内・空欄・相対パスの拒否、保存先作成失敗時に全ソース不変。
- WPF 203項目: 3画面で設定入力・無効化・再解析不要・再起動後の設定復元・選択ファイルだけの外部バックアップ。
  実画面の画像でもバックアップ欄と既存プレビュー・操作ボタンの配置を確認した。
- Consoleの4コマンド経路でカスタム保存先への適用・バックアップの元バイト一致・ソース内指定の拒否を確認。

テストのバックアップはテスト用フォルダー内のソース外に保存する。Engine・Lyra・BlockBreakerには適用していない。
