# 入力内容の保存とフォルダードロップ

[目次](README.md) / [Issue #16](https://github.com/posita33/UEEtc/issues/16)

CPU 画面とイベント画面のソースパス、イベント画面の絞り込み文字を保存し、次の起動時に復元します。イベント候補で手動編集したカウンター名と Insights 表示名も、同じソースルート・候補 ID に対応する候補を再解析した際に復元します。入力を空にした場合も保存するので、以前の値へ勝手に戻りません。

保存するのは入力内容です。解析・付与後プレビューの本文、候補のチェック状態、適用できる変更案は復元しません。再起動後は解析・選択・プレビューをやり直します。名前を復元した候補も、ソースの意味を確認してから選択してください。

## 操作

- 手入力・フォルダー選択・ドロップのどの方法で設定しても、ソースパスを保存します。
- エクスプローラー等からフォルダーをソースパス欄へ 1 つドロップすると、フルパスを設定します。解析は自動実行しません。
- ファイルや複数フォルダーは受け付けず、元の入力を保ちます。解析等で欄が無効な間のドロップも受け付けません。フォルダー自体を移動・コピーする操作ではありません。
- パスが変更されると、従来どおり古いプレビューや適用状態を無効化します。

## 保存先と実装

保存先は `%LOCALAPPDATA%/UEEtc/input-settings.json` です。リポジトリやゲームの Source フォルダーには設定ファイルを作りません。CPU とイベントのパスは別のキーで保持します。候補の編集はソースルートのハッシュと候補 ID に対応付けます。名前だけを保存し、すべてのソース本文は保存しません。

`UEEtc.Wpf.InputAssistance` に共通部品を配置しました。

| 型 | 担当 |
| --- | --- |
| `InputSettingsStore` | 読み込み、アプリ内で共有する設定値、UTF-8 の JSON 保存、一時ファイルからの置換 |
| `RememberedInputs` | TextBox の復元と変更監視、400ms の保存待ち、ウィンドウ終了時の保存 |
| `FolderDropInput` | TextBox 本来の処理より前に PreviewDragOver / PreviewDrop を処理し、フォルダーパスを設定 |

入力のたびにディスクへ書き込まず、入力が止まってから保存します。ウィンドウを閉じる際にも保存を試みます。同じアプリ内の複数ウィンドウは設定ストアを共有します。複数のアプリプロセスから同時に編集する場合は、最後に保存した側の内容になります。

設定ファイルがない場合は空の入力で始めます。破損や読み取り失敗でアプリを終了せず、画面の状態欄へ実際の失敗を表示します。保存できなくても入力値はメモリーに残します。破損した JSON は、入力を変更して保存できた時点で新しい設定に置き換わります。解析・ソース適用は入力設定の保存とは独立しています。

## 検証

WPF スモークテストは 50 チェックが成功しました。従来の画面・選択・プレビュー検証に加え、別ストア／ウィンドウでの再起動相当の復元、名前復元後も選択 0 件、空文字の保存、日本語とスペース、フォルダードロップ、ファイル・複数フォルダーの拒否、無効な欄での拒否、破損 JSON、保存失敗、一時ファイルの後始末を確認しました。ドラッグイベントは WPF の実際のルーティングハンドラーに渡しています。エクスプローラーからの OLE ドラッグ操作自体は自動化していません。

テストは一時フォルダーへ専用ストアを渡し、実ユーザーの入力設定を変更しません。Core の解析・付与処理は変更していません。

リポジトリルートでの再現コマンド:

```powershell
dotnet build UEEtc.sln -c Release
dotnet run --project tests/UEEtc.Wpf.SmokeTests -c Release --no-build
```
